# Architecture Decision Records

## 철학
MVP다. 합의된 유저 플로우를 지키는 범위에서 파일 수·추상화·외부 의존성을 최소로 한다. 작동하는 최소 구현을 고르고, 사용자 입력과 결과를 잃지 않는 것을 품질의 기준으로 삼는다.

---

### ADR-001: Next.js App Router + Route Handler
**결정**: Next.js 16 App Router로 화면과 API(`/api/thumbnails`)를 한 프로젝트에 둔다.
**이유**: OpenAI API 키를 서버에만 두면서 별도 백엔드 없이 하나의 코드베이스로 끝낼 수 있다.
**트레이드오프**: 장시간 요청(최대 2분)이 서버리스 플랫폼 제한에 걸릴 수 있다. 배포는 MVP 범위 밖이며 로컬 실행을 기준으로 한다.

### ADR-002: 이미지 모델 `gpt-image-2.5-flare` 고정
**결정**: OpenAI `gpt-image-2.5-flare`만 쓰고, `quality: "high"`로 고정한다.
**이유**: OpenAI가 일반 용도의 기본값으로 권장하는 모델이고, 상위 모델보다 빠르다. 썸네일 문구 가독성을 위해 품질은 high로 둔다.
**트레이드오프**: 인물 합성·편집 정밀도가 더 높은 `gpt-image-2.5-sunburst`와 모델 선택 UI를 포기한다.

### ADR-003: 출력 1280×720 JPEG
**결정**: `size: "1280x720"`, `output_format: "jpeg"`로 생성한다.
**이유**: 유튜브 권장 썸네일 해상도(16:9)를 후처리 없이 바로 얻는다. 모델의 custom size 규칙(16의 배수, 픽셀 수 범위)을 충족하고, JPEG가 PNG보다 빠르고 가볍다.
**트레이드오프**: 2K 이상 고해상도와 투명 배경을 포기한다. 실제 API가 이 크기를 거부하면 `services/thumbnail.ts`의 상수 한 곳만 바꾼다.

### ADR-004: 템플릿 기반 프롬프트 보강 (추가 LLM 호출 없음)
**결정**: 서버에서 고정 템플릿(`buildPrompt`)으로 사용자 입력을 감싸 썸네일 가이드·문구 정확도·얼굴 유지 지시를 더한다.
**이유**: 지연과 비용이 늘지 않고, 순수 함수라 테스트하기 쉽다. 문구를 별도 필드로 받아 철자 그대로 넣도록 지시하면 텍스트 렌더링 정확도가 올라간다.
**트레이드오프**: LLM이 프롬프트를 지능적으로 다시 쓰는 방식의 품질 향상을 포기한다.

### ADR-005: 세션 메모리 이력 + stateless 서버
**결정**: 생성 결과(라운드)는 클라이언트 `useState`에만 두고, 서버는 이미지를 저장하지 않는다.
**이유**: DB·스토리지·인증이 필요 없다. 사용자는 세션 동안 이전 시안과 비교할 수 있고, 이탈 경고로 실수에 의한 유실을 줄인다.
**트레이드오프**: 새로고침하거나 탭을 닫으면 결과가 사라진다.

### ADR-006: 스트리밍·자동 재시도·서버 타임아웃 미채택
**결정**: 일반 JSON 응답을 쓰고, OpenAI SDK `maxRetries: 0`으로 둔다. 타임아웃은 클라이언트 180초 하나만 둔다(클라이언트가 abort하면 `request.signal`로 OpenAI 호출도 중단된다).
**이유**: 구현이 단순하다. 이미지 생성이 길어서 자동 재시도는 대기 시간과 비용을 몇 배로 늘린다. 재시도 여부는 에러 카드의 `retryable`을 보고 사용자가 정한다.
**트레이드오프**: 생성 중 부분 미리보기(partial images)를 포기한다. 대기 중에는 자리표시자와 경과 시간만 보여준다.

### ADR-007: 에러는 `{ message, retryable }` 하나로 표현
**결정**: 에러 코드 체계를 따로 두지 않는다. 서버는 `toUserError`로 HTTP status와 `{ message, retryable }`만 돌려준다.
**이유**: UI가 분기하는 기준은 "다시 시도 버튼을 보여줄지" 하나뿐이다.
**트레이드오프**: 에러 종류별 통계나 세분화된 UI 처리가 필요해지면 코드 체계를 다시 도입해야 한다.
