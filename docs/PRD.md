# PRD: thumbnail-maker

## 목표
유튜브 채널 운영자가 말하듯 설명만 하면, 클릭을 부르는 고품질 썸네일을 쉽고 빠르게 만들어 영상 유입을 늘린다.

## 사용자
유튜브 채널을 운영하는 개인 크리에이터. 디자인 툴에 익숙하지 않고 영상마다 빠르게 썸네일을 뽑아야 한다.

## 핵심 기능
1. **썸네일 생성**: 설명 프롬프트(필수) + 썸네일 문구(선택) + 사진(선택, 1장) + 시안 개수(2/3/4)를 입력하면 1280×720 JPEG 시안을 여러 장 만든다.
2. **비교와 개선**: 세션 동안 생성 결과(라운드)를 쌓아 비교한다. 작게 보기로 가독성을 확인하고, 같은 입력으로 다시 생성하거나 고른 시안을 수정 요청으로 다듬는다.
3. **다운로드**: 원하는 시안을 유튜브 업로드용 JPG로 내려받는다.

## MVP 제외 사항
- 로그인·결제·사용량 관리
- 생성 이력의 영구 저장 (세션 메모리만 사용, 새로고침하면 사라짐)
- 참조 사진 여러 장 (1장만)
- 결과물의 텍스트·레이어 후편집 에디터
- 유튜브 업로드 연동
- 스트리밍 미리보기, rate limit, 배포 설정

## 디자인
- 다크모드 고정, 도구처럼 보이는 미니멀 UI (상세는 `docs/UI_GUIDE.md`)
- 무채색 + 흰색 Primary 버튼, 에러만 빨강

## 2. 화면

**레이아웃**: 1024px 이상에서는 2단(좌: 입력 패널 sticky, 우: 결과 패널), 그보다 좁으면 1단(입력 → 결과)이다. 생성을 시작하면 새 카드로 스크롤한다.

### 2-1. 첫 진입 (빈 상태)
```
┌ 썸네일 메이커 ─────────────────────────────────────────────────────────┐
│ 어떤 썸네일을 원하세요? *          │  썸네일, 이렇게 만들어요  (빈 상태)  │
│ ┌──────────────────────────────┐  │  ① 원하는 썸네일을 설명해요          │
│ │ 예) 어두운 우주 배경에 놀란   │  │  ② 문구·사진을 더하면 더 정확해요    │
│ │ 표정의 내 얼굴을 오른쪽에 크게 │  │  ③ 시안을 비교해 고르고 내려받아요   │
│ └─────────────────────── 0/2000┘  │                                     │
│ 예시로 시작: [게임] [요리] [재테크] │                                     │
│ 썸네일 문구 (선택 · 15자 이내 권장) │                                     │
│ ┌──────────────────────── 0/40 ┐  │                                     │
│ 사진 (선택 · 1장)                  │                                     │
│ ┌ 끌어다 놓거나 클릭해서 올리기 ┐  │                                     │
│ └ PNG·JPG·WEBP, 10MB 이하 ─────┘  │                                     │
│ 시안 개수  (2) 3  4               │                                     │
│ [        썸네일 만들기        ]    │                                     │
└────────────────────────────────────┴─────────────────────────────────────┘
```
- 설명과 문구 아래에 글자 수 카운터를 둔다. 제한을 넘으면 카운터가 빨간색이 된다.
- 예시 칩은 설명과 문구가 **둘 다 비어 있을 때만** 보인다. 클릭하면 두 칸에 예시가 채워진다.
- 사진을 첨부하면 드롭존이 `[미리보기] 파일명 · [삭제]`로 바뀐다. 아래에 "얼굴이 잘 보이는 정면 사진일수록 좋아요" 팁을 표시한다.
- 시안 개수 아래에 "시안이 많을수록 오래 걸려요"를 표시한다.

### 2-2. 라운드 카드 (결과 패널, 최신이 맨 위)
```
#3 새로 만들기 · 2장                   23초 경과 · 보통 30초~2분  [취소]
[░░ 16:9 ░░] [░░ 16:9 ░░]                                    ← 생성 중

#2 수정 · 기반 #1-2 · 2장                        [같은 입력으로 다시 생성]
"문구를 더 크게, 배경을 빨간색으로" · 새 문구: 월 천만원 버는 법
[  #2-1  ] [  #2-2  ]                                        ← 완료
 [다운로드] [작게 보기] [이 시안으로 수정하기]   (시안마다)

#1 새로 만들기 · 실패                                           [닫기]
⚠ 요청이 몰려 있어요. 잠시 후 다시 시도해주세요.  [다시 시도]   ← 실패
```
- 라운드 번호(`#seq`)는 세션 동안 1부터 증가한다. 시안 번호는 `#라운드-순번`이다.
- 헤더 아래에 입력 요약을 표시한다. 새로 만들기는 설명 앞부분, 문구, "사진 첨부" 여부를 보여준다. 수정은 "기반 #x-y", 수정 요청, 새 문구를 보여준다.
- 생성 중 카드는 시안 개수만큼 16:9 자리표시자(펄스)를 보여주고, 경과 초를 1초마다 갱신한다.
- 받은 장수가 요청보다 적으면 "요청한 3장 중 2장만 만들어졌어요"를 표시한다.

### 2-3. 수정 모드 (입력 패널이 전환됨)
```
시안 수정                                   [← 새로 만들기로 돌아가기]
┌──────────┐ 기반 시안 #1-2
│  thumb   │ 이 시안을 바탕으로 바꿀 부분만 고쳐요
└──────────┘
무엇을 바꿀까요? *
┌───────────────────────────────── 0/2000┐
│ 예) 문구를 더 크게, 배경을 빨간색으로    │
└─────────────────────────────────────────┘
새 문구 (선택 · 비우면 기존 문구 유지)  ┌──────── 0/40┐
시안 개수  (2) 3  4
[        수정 시안 만들기        ]
```
- 사진 입력과 예시 칩은 숨긴다.
- 새로 만들기 모드에서 입력한 값은 **그대로 보존**했다가, 돌아가면 복원한다.
- 다른 시안에서 [이 시안으로 수정하기]를 누르면 기반 시안만 바꾸고 수정 요청 텍스트는 유지한다.

### 2-4. 작게 보기 (다이얼로그)
```
작은 화면에서 이렇게 보여요                                        [닫기]
┌──────────────────────────┐     ┌──────────┐ ▬▬▬▬▬▬▬▬
│   약 360px (모바일 피드)   │     │ 약 168px │ ▬▬▬▬▬
└──────────────────────────┘     └──────────┘ (추천 영상 목록)
▬▬▬▬▬▬▬▬▬▬▬▬  ▬▬▬▬▬▬ (제목 자리)
문구가 이 크기에서도 한눈에 읽히는지 확인해보세요.
```
- `<dialog>`를 쓰고 Esc로 닫힌다. 제목 자리는 회색 막대 placeholder만 쓰고, 유튜브 로고나 UI는 흉내 내지 않는다.

## 3. 동작 규칙
- **제출**: 생성 버튼은 생성 중이 아니면 항상 활성이다. 누르면 클라이언트에서 검증하고, 실패하면 필드 아래에 메시지를 띄우고 첫 오류 필드로 포커스한다(요청은 보내지 않음).
- **입력 보존**: 성공·실패·취소 어떤 경우에도 입력 패널 값을 지우지 않는다. 사용자는 바로 고쳐서 다시 만들 수 있다.
- **동시 생성 1건**: 생성 중 카드가 있으면 [썸네일 만들기], [수정 시안 만들기], [같은 입력으로 다시 생성], [다시 시도]를 모두 비활성으로 둔다. 이전 라운드의 다운로드·작게 보기는 계속 쓸 수 있다.
- **같은 입력으로 다시 생성**: 그 라운드가 저장한 입력 스냅샷(사진 File 포함)을 그대로 보내 새 라운드를 만든다. 입력 패널 값은 바꾸지 않는다.
- **다시 시도**: 실패한 라운드의 스냅샷을 다시 보내며, 실패 카드를 새 생성 중 카드로 교체한다.
- **이 시안으로 수정하기**: 입력 패널을 수정 모드로 전환한다(좁은 화면이면 입력 패널로 스크롤). 제출하면 기반 시안 data URL을 Blob으로 바꿔 `image`에 담고 `mode=revise`로 보낸다.
- **취소**: fetch를 abort하면 서버는 `request.signal`로 OpenAI 호출도 중단한다. 카드를 목록에서 제거하고 "생성을 취소했어요"를 알린다.
- **클라이언트 타임아웃**: 180초 동안 응답이 없으면 요청을 abort하고 타임아웃 에러로 처리한다.
- **다운로드**: `<a download>`로 data URL을 `thumbnail-{라운드}-{순번}.jpg`로 저장한다.
- **사진 첨부**:
  - 파일 입력에 `accept="image/png,image/jpeg,image/webp"`를 쓴다. iOS는 HEIC를 자동으로 JPG로 변환한다.
  - 드래그로 여러 장을 놓으면 첫 장만 받고 "사진은 1장만 쓸 수 있어 첫 번째 사진만 올렸어요"를 안내한다.
  - 형식·용량이 맞지 않으면 첨부하지 않고 드롭존 아래에 메시지를 띄운다. 기존 사진이 있었다면 그대로 둔다.
- **이탈 경고**: 생성 중이거나 완료된 카드가 1개 이상이면 `beforeunload` 경고를 띄운다.
- **접근성**: 생성 시작("썸네일을 만들고 있어요")·완료·실패·취소를 aria-live 영역 하나로 알린다. 필드 에러는 `aria-describedby`로 연결한다.

## 4. 검증과 에러

### 4-1. 입력 검증
규칙과 상수는 `src/lib/validation.ts` 한 곳에 두고 클라이언트와 서버가 함께 쓴다.

| 대상 | 규칙 | 메시지 |
|---|---|---|
| 설명 (create) | trim 후 비어 있음 | 어떤 썸네일을 원하는지 적어주세요 |
| 수정 요청 (revise) | trim 후 비어 있음 | 무엇을 바꿀지 적어주세요 |
| 설명/수정 요청 | 2000자 초과 | 2000자 이내로 줄여주세요 |
| 문구 | 40자 초과 | 40자 이내로 줄여주세요 |
| 사진 | png/jpeg/webp가 아님 | PNG, JPG, WEBP 사진만 올릴 수 있어요. 아이폰 HEIC 사진은 JPG로 바꿔서 올려주세요 |
| 사진 | 10MB 초과 | 10MB 이하 사진만 올릴 수 있어요 |
| (서버) revise | 이미지 없음 | 수정할 시안이 없어요 |
| (서버) count | 2·3·4가 아님 | 시안 개수는 2~4장 중에서 골라주세요 |

### 4-2. 생성 에러
API 실패 응답은 `{ "error": { "message": string, "retryable": boolean } }` 형식이다. 에러 카드는 `retryable`이 true일 때만 [다시 시도]를 보여주고, [닫기]는 항상 보여준다.

| 상황 | HTTP | 메시지 | retryable |
|---|---|---|---|
| 입력 검증 실패 | 400 | (4-1의 메시지) | false |
| OpenAI 정책 거부 (`moderation_blocked`, `content_policy_violation`) | 422 | 이미지 생성 정책에 걸렸어요. 실존 유명인, 폭력·선정적 표현, 상표·로고를 빼고 다시 시도해보세요 | false |
| OpenAI 429 (`insufficient_quota` 제외) | 429 | 요청이 몰려 있어요. 잠시 후 다시 시도해주세요 | true |
| API 키 없음, OpenAI 401/403, `insufficient_quota` | 500 | 서비스 설정에 문제가 있어요. 운영자에게 문의해주세요 | false |
| 그 외 OpenAI 오류 | 502 | 이미지 생성 서버에 일시적인 문제가 있어요 | true |
| (클라이언트) 네트워크 실패 | — | 인터넷 연결을 확인하고 다시 시도해주세요 | true |
| (클라이언트) 180초 초과 | — | 생성이 너무 오래 걸려 멈췄어요. 시안 개수를 줄이거나 다시 시도해보세요 | true |

- 서버는 자동 재시도를 하지 않는다(SDK `maxRetries: 0`). 재시도 여부는 사용자가 결정한다.
- 클라이언트에는 OpenAI 원문 에러나 스택을 보내지 않는다. 서버 로그에는 HTTP status와 upstream status만 남긴다.

## 5. API — `POST /api/thumbnails`

요청은 `multipart/form-data`다.

| 필드 | 타입 | 필수 | 제약 |
|---|---|---|---|
| `mode` | `"create"` \| `"revise"` | ❌ | 기본 `create` |
| `prompt` | string | ✅ | trim 후 1~2000자. create는 썸네일 설명, revise는 수정 요청 |
| `caption` | string | ❌ | trim 후 0~40자. 썸네일에 정확히 들어갈 문구 (revise에서는 새 문구) |
| `image` | File | create ❌ / revise ✅ | png/jpeg/webp, 10MB 이하, 1장 |
| `count` | `2` \| `3` \| `4` | ❌ | 기본 2 |

**응답**
- 성공 `200`: `{ "images": ["data:image/jpeg;base64,...", ...] }` (최대 count장)
- 실패: §4-2 형식

**OpenAI 호출** (`src/services/thumbnail.ts`)
- 이미지가 없으면 `client.images.generate`, 있으면 `client.images.edit`(`image`에 업로드 파일)를 쓴다.
- 공통 파라미터: `model: "gpt-image-2.5-flare"`, `size: "1280x720"`, `quality: "high"`, `output_format: "jpeg"`, `n: count`. 요청 옵션으로 `signal`을 넘긴다.
- 응답 `data[].b64_json`을 `data:image/jpeg;base64,...`로 바꾼다.

**프롬프트 템플릿** (`buildPrompt`)
- **create**: 유튜브 썸네일 가이드(16:9, 시선이 꽂히는 초점 하나, 고대비, 작은 화면에서도 읽히는 크고 굵은 글씨) 뒤에 사용자 설명을 **원문 그대로** 붙인다.
  - 문구가 있으면: 그 문구를 철자 그대로, 한 번만, 크고 굵게 넣고 다른 글자는 넣지 말 것. 한글을 정확히 렌더링할 것.
  - 문구가 없으면: 설명이 요구한 글자 외에는 넣지 말 것.
